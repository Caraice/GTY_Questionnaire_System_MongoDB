# 测试步骤

## 准备

保持四个文件夹同级；先按 ../01_可运行代码/配置说明.md 创建 .venv、安装 requirements-lock.txt 并启动MongoDB。自动化测试还需Node.js，本项目本机实际使用的版本会写入测试结果。自动化直接创建应用，不要求API服务器已启动；浏览器手工测试需Start.cmd启动API。

测试连接默认 mongodb://127.0.0.1:27019；自定义连接需在同一PowerShell窗口设置MONGODB_URI。测试账号与业务数据在随机UUID隔离库中创建，库名前缀为survey_test_等，不清空原业务库。测试库保留可供查询，需要具备创建库/集合/索引的权限。不要用会被他人并发修改的演示库做手工结果对照。

## 自动执行全部测试

在“03_测试用例”打开PowerShell：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\运行全部测试.ps1
```

脚本强制开启RUN_MONGO_TESTS=1，先跑11个Python文件，再跑5个Node文件。输出写入测试输出/Python测试.log、Python测试.xml、Node测试.log。缺MongoDB、Python、Node或依赖均不应视为通过。默认解释器是同级01_可运行代码/.venv/Scripts/python.exe；也支持明确复用本机已有环境：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\运行全部测试.ps1 -PythonExe '你的现有虚拟环境\Scripts\python.exe' -NodeExe '你的node.exe路径'
```

也可分别运行：

```powershell
$env:RUN_MONGO_TESTS = '1'
$env:PYTHONDONTWRITEBYTECODE = '1'
..\01_可运行代码\.venv\Scripts\python.exe -B -X utf8 -m pytest -q -s -p no:cacheprovider --junitxml=测试输出/Python测试.xml
node --test 自动化测试/test_editor_state.mjs 自动化测试/test_survey_state.mjs 自动化测试/test_fill_state.mjs 自动化测试/test_view_state.mjs 自动化测试/test_rules_state.mjs
```

当前版本预期Python283项通过、失败/错误/跳过均为0，Node18项通过、0失败。不要把未开启集成测试时的“部分通过、其余跳过”当成完整验收。实际结果见测试结果.md；每项详细输入与断言见自动化测试代码，重点用例的步骤/输入/输出/结果整理在测试用例.md。

## 本人浏览器验收顺序

1. 确认 /health 版本0.8.0，注册发布者A与填写者B（自行设密码，不使用他人账号）。A创建问卷并允许匿名、多次填写，先不发布。
2. 添加单选、多选、数字、文本和可选建议题，保存、重载，核对顺序、选项、必答、限制；排序、删除一次核对稳定ID。全空白题干/选项应提示错误。
3. 通过“配置跳转规则”添加并保存条件。按测试用例的3份浏览器样本设置题目与规则后发布；验证发布后定义只读。无需在/docs配置。
4. 在同一页签换B登录再打开分享链接。分别故意漏必答、多选超限、输入过短文本和超范围数字，应有提示且不能成功保存。数字0必须通过。
5. 按3份样本顺序提交；返回改答检查旧分支答案已清理；仅有成功回执才记保存。进入“我填写的问卷”回看每份实际内容，匿名记录也能看。
6. 换A登录，点击“查看实时统计”，检查总3、每题回答数3/2/2/2/1、年龄均值10；选择年龄单题应与整卷一致。填写页右上角也能直接进入当前问卷统计。
7. 测试不允许匿名、不允许多次的另一份问卷：匿名请求被拒绝，同账号第二次新提交被拒绝；自动化另覆盖并发、幂等与数据库故障。
8. 手动关闭或设很近的未来期限等待到点：刷新填写和新提交应拒绝；已保存回执重试和本人历史仍可查。已截止但未关闭可延长期限，已手动关闭不能恢复。
