## 记录 003 原始答案类型与严格逐题校验

- 工具：Codex AI 编程助手，本地 Python/Pydantic 探测、代码编辑、pytest 与真实 MongoDB 回归测试。
- 用户原始提示词：“我发现当前 Submission 会把 true 转成 1，并接受 NaN/Infinity。请保留答案原始类型再按题型严格校验，实现 validation.py，覆盖必答、选择数量、文本长度、数字范围及整数限制，且确保数字 0 合法”。
- 确认的旧代码问题：原联合类型将 true/false 转为 int 1/0，允许 float NaN/Infinity；先前 AI 生成的数据契约确有这个缺陷。
- 方案和产出：用 JsonValue 保留 JSON 原始类型并配置禁止非有限数；完成 validate_answer 纯函数；必答按类型判断空值，禁止错误类型和重复选项；数字拒绝 bool/字符串/非有限值，0 合法；数学整数允许 1.0 且保留 float 类型。
- 附带修复：默认请求校验错误响应回显 NaN 会产生 JSON 序列化 ValueError。错误响应只保留 type/loc/msg，使非法数值安全返回 422。使用原始 NaN、Infinity、-Infinity、1e999 HTTP 请求做回归。
- 实际验证：全部 133 项 Python 测试通过，其中新增 99 项模型、逐题校验和 HTTP 边界测试；保留 1 条原有 Starlette 测试适配弃用警告。受限执行环境中的 asyncio/HTTP 诊断曾停滞，结束明确匹配本次命令的进程后，在本机允许环境中完成验证；不把停滞写成业务测试通过。
- 学生本人是否审阅与修改：是。
- 边界：校验引擎已实现，后续仍需在服务端实际访问路径与提交流程调用；没有把 501 提交接口改成伪成功。
