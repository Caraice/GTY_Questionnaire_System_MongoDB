# 基于 MongoDB 的问卷系统 第二阶段

这是我在第一阶段代码上继续做的问卷系统，使用Python、FastAPI、PyMongo和原生网页，版本 **0.11.0**。原有注册登录、四题型、跳转、发布关闭、截止时间、真实提交、整卷/单题统计和个人填写历史仍保留。

第二阶段增加了题库、指定版本导入、保存新版本与另存新题、版本差异与恢复、按版本共享和撤销、引用明细、草稿主动升级、跨问卷统计。不同窗口保存冲突返回409；列表与跨卷内容支持分页。

## 怎么运行

在本目录打开PowerShell，先安装依赖，再启动：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
$env:MONGOD_EXE = 'C:\MongoDB\bin\mongod.exe'
.\Start.cmd
```

上面的MongoDB程序路径要换成自己安装的位置。直接双击Start.cmd前必须准备好本目录.venv，不能把开发目录的虚拟环境当作提交包环境。已有MongoDB可设置MONGODB_URI；.env.example只是参考，不自动加载。详见 [配置说明](配置说明.md)。

工作台 http://127.0.0.1:8000；健康检查 /health 应显示version=0.11.0。默认MongoDB端口27019、数据库survey_stage1保持第一阶段配置，不因阶段升级换库。启动创建缺少的集合和索引，不自动迁移旧题。

## 怎么操作

1. 注册登录，创建问卷草稿，编辑四种题型并保存；通过按钮配置跳转规则，再发布分享。
2. 进入“我的题库”，创建题库和题目，勾选归属；移出题库不删除题目。
3. 在问卷编辑页“从题库添加”预览具体版本；同题可重复添加，每次有独立实例ID。
4. 进入“版本历史、共享与引用”，编辑后可保存新版本或另存新题；恢复旧版生成新的内容版本。
5. 按版本共享给已注册账号，对方可以导入或另存；共享不包含修改原题或查看他人答卷的权限。
6. 草稿可主动升级单个实例，保留ID并重查跳转；已发布问卷保持冻结。撤销共享只停止新的使用准入，已导入内容继续保留。
7. 发布者用“查看实时统计”查看一份问卷；题目卡片“查看题目统计”查看按版本的跨卷结果，必要时检查选项映射和单位后合并。
8. 题库、题目、历史、引用及跨卷文本内容均有翻页按钮。跨卷内容每页100条，计数和均值使用全部有效回答；合法0计入，跳题排除。

填写者仍通过分享链接登录填写，并在工作台“我填写的问卷”回看已提交内容。不会在刷新后自动恢复尚未提交的草稿。

## 怎么测试

```powershell
Set-Location ..\03_测试用例
powershell -NoProfile -ExecutionPolicy Bypass -File .\运行全部测试.ps1
```

需可连接的MongoDB与Node.js。脚本默认使用本目录.venv，也可明确传入-PythonExe和-NodeExe。完整步骤、输入输出及重跑结果见 [测试步骤](../03_测试用例/测试步骤.md)、[测试结果](../03_测试用例/测试结果.md)。

## 代码与材料

app/api、services、repositories沿用分层，app/domain负责规则/校验与内容兼容；web放网页，database放schema与迁移，scripts放启动、初始化及固定数据查询测量。源码内不再重复放docs和tests。

技术材料在 [02_文档](../02_文档/系统说明.md)，测试在03，报告和AI日志在04。schema.json/indexes.json由实际代码与隔离数据库生成，可执行定义仍以database/schema.py、library_schema.py、bank_schema.py为准。第一阶段基线见04/阶段基线。

当前不提供跨账号答卷开放、自动单位换算、跨卷人员去重或额外缓存；全新电脑安装、大规模压力和正式库恢复尚未验证。
