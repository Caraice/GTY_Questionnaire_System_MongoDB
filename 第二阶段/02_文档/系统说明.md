# 系统说明

## 目标和范围

本系统面向问卷发布者与填写者，完成注册登录、创建问卷、四种题型、配置跳转、发布关闭与期限、登录填写、真实保存、本人历史以及创建者统计。程序版本0.11.0，第二阶段新增题库、内容版本、共享、引用、主动升级和跨问卷统计。业务数据全部存MongoDB，不使用关系数据库或现成问卷框架。

系统采用 Python、FastAPI、PyMongo 与原生 HTML/CSS/JavaScript。前端无需构建。HTTP路由处理输入、身份与响应；services组织业务；domain实现纯函数校验和跳转；repositories负责MongoDB查询与聚合。前端提供及时提示，服务端独立校验，不能靠修改页面绕过权限和规则。配置及安装见 [配置说明](../01_可运行代码/配置说明.md)。

## 发布者的操作

1. 打开工作台并注册、登录。“我的问卷”显示本人问卷；创建表单位于“创建问卷”页签。
2. 输入标题、说明，可设截止时间、允许匿名、允许同一账号多次填写。日期格式为 yyyy/mm/dd hh:mm，按本机时区输入，服务端统一UTC。
3. 保存草稿后点击“编辑题目”。添加单选、多选、文本、数字；编辑题干、必答、选项和限制；可排序、删除，点击“保存题目”。只含空格的题干或选项不能保存。
4. 点击“配置跳转规则”，选择来源题、条件、回答值和目标题，点击添加并保存。可以上移、下移、删除规则；无匹配时顺序继续。来源和目标用真实题目选择，跳转保存在问卷中，不写死在代码。
5. 例如第1题选B跳到第3题：来源选择第1题，条件“等于”，选择B，目标选择第3题；多选可选择“包含任一/全部”；数字可选择闭区间；文本可选择等于或包含。目标只能向后或“结束问卷”，多条匹配时先执行排在前面的规则。无需访问API文档完成配置。
6. 返回工作台点击“发布问卷”。服务器重新检查题目、规则与期限；成功后题目、选项、题序和规则冻结。复制分享链接发给填写者。
7. 点击绿色“查看实时统计”，查看整卷或选择单题；可手动刷新，页面可见时每10秒自动刷新。自己问卷的填写页右上角也可直接进入统计。只有问卷创建者能查看该问卷统计。
8. 工作台可修改截止时间，延长、缩短或清除。已截止但未手动关闭的问卷可通过延长恢复；点击“关闭问卷”后不可重新开放。标签按实际状态显示草稿、已发布、已截止、已关闭。

## 填写者的操作

1. 在同一浏览器页签登录后打开 /survey/{share_id} 分享链接。未登录按页面提示登录后返回；草稿、关闭或截止时不能获取可填写定义。
2. 按顺序作答，下一步会校验并按配置规则跳题；数字0可正常填写。漏必答、选项数量不符、文本长度或数字范围不符时显示对应错误。
3. 可以返回上一题修改；分支变化后清理不再访问题目的旧答案。跳过的必答题不要求填写，不能夹带跳过题的答案。
4. 确认页提交后，仅收到服务器回执才显示成功。匿名仅在发布者允许时可选；多次填写也由问卷配置决定。
5. 网络结果不明时保持当前内容，使用页面原提交重试，避免重复保存；同请求成功回执可在截止或关闭后重放。
6. 返回工作台“我填写的问卷”，分页查看本人每次已保存答卷及实际回答。旧匿名记录本人也能看，其他用户包括发布者不能读取其个人详情。问卷关闭或截止后历史仍可读。


## 第二阶段题库 版本与共享操作

## 页面怎么操作

1. 工作台右上角进入“我的题库”，创建题库。点“新建题目”选择单选、多选、文本或数字，设置题干、选项和限制后保存。新题先在“全部题目”中显示，勾选归属后即可加入多个题库；取消勾选只移除关联。
2. 题目卡片点“版本历史、共享与引用”，可预览版本、展开差异、查看来源和引用问卷。选择“编辑此版本／另存为新题”，前者追加本题版本，后者新建独立题目并记录来源。新题不会自动继承原题的题库归属或共享权限，需要自行勾选。
3. 历史页点击“恢复 v1 为新版本”，在当前头版本后追加。例如已有 v1、v2、v3，恢复后得到 v4，内容取自 v1，前一版本仍是 v3，恢复来源是 v1。
4. 展开某个版本的“共享版本”，输入已注册账号，点击“共享此版本”。对方在“我的题库 → 查看题库 → 共享给我的题目”看到获准的版本；没有共享的其他版本不会出现。接收方若要修改，先进入编辑页，改好后“另存为新题”，不能保存到原题的版本链。
5. 问卷编辑页先保存当前修改，再点“从题库添加”。选择题库或“共享给我的题目”，选择题目、具体版本并预览，确认添加。每次添加立即落库；同题同版本可以再次添加，每次生成新实例 ID。
6. 草稿发现当前账号可用的新版，会显示提示。点击“预览并主动更新此题”，选择版本并确认替换。仅这个实例更新，ID 和排序不变，其余实例不跟随变化。若新版本会破坏跳转选项或来源题型，会拒绝更新，先调整规则再试。已发布或关闭的问卷不能更新题目。
7. 原作者可在版本历史中撤销共享。撤销后不能进行新的导入、更新或另存；此前已导入的问卷和已另存的独立题目继续保留内容。撤销不会回收答卷，也不会删除历史版本。

## 第二阶段题目统计

## 页面怎么操作

1. 登录后进入“我的题库”，在题目卡片点击“查看题目统计”。版本历史中有“查看本版本跨问卷统计”，问卷统计中的来源按钮也能进入。未登录会先登录，再返回原统计页。
2. 页面先逐版本显示统计，展开“参与的题目实例”查看问卷、状态、题号和版本。展开“排除的题目实例”查看草稿、本地修改或来源异常等原因。结果权限之外的问卷完全不展示，连标题和数量也不列作排除明细。
3. 勾选至少两个版本，选择基准版本，再点“检查并合并统计”。页面列出通过和未通过检查的版本及原因；至少两个兼容版本且基准版本通过时才给出合并结果，不会偷偷换掉基准版本。
4. 选择题的ID相同可直接对应。ID不同时，逐项选择来源选项对应的基准选项；必须完整、一一对应，不允许漏项或多个来源合为一个选项。即使选项文字一样，也不会自动匹配。
5. 数字题显示版本声明的单位。旧版未声明时，在“本次确认单位”中填写；确实无单位可填“无单位”。各版本必须一致才合并，不进行 kg/g 等换算。确认只作用于本次请求，刷新后需重新填写，不改写旧版本。声明单位已有值时不能用确认值覆盖。
6. 点击“刷新统计”重新读取数据库。本页按操作刷新，没有新增定时轮询。文本和数字内容每页100条，可用上一页/下一页查看；页面显示本页条数与总回答数，计数、选项次数和平均值使用全部有效回答。

数字题编辑器也增加了“计量单位（可选）”。修改单位时仍应保存新版本；既有已发布问卷继续使用旧快照。

## 三个数各是什么意思

| 指标 | 本轮口径 |
| --- | --- |
| 涉及问卷数 survey_count | 当前账号有结果权限、已发布或已关闭，且至少含一个合规来源实例的问卷数；包括暂无答卷的问卷，排除草稿。已截止的已发布问卷仍可统计。 |
| 答卷数 response_count | 这些问卷当前冻结定义下的答卷记录数，包含跳过本题的答卷；同一答卷在本组只计一次。 |
| 题目回答次数 answer_count | 实际填写路径中、符合各自来源版本限制的有效实例回答次数；同题在同卷出现两次可计两次，跳题、空白和非法值不计。 |

因此回答次数可以大于答卷数。各版本的答卷数可能有交集，合并时重新在 MongoDB 对参与问卷取并集，不能直接相加版本卡片上的数。多人、多次和匿名提交都按实际答卷记录计算，不读取账号或匿名标识来做跨问卷人员去重，也不把次数称为独立人数。

单选按选项计回答次数，多选显示各选项次数及选择总次数，文本展示有效内容，数字展示有效值及平均数。合法数字0进入计数和平均数分母；布尔值、数字字符串、NaN/Infinity、越界或不满足整数限制的历史数据被排除。所有答案继续按其原版本限制校验，合并不会把新版合法的15套入旧版上限10后丢弃。

## 分页与当前边界

题库/题目每页20项，历史每页10版，引用20实例，跨卷统计文本/数字每页100条，按页面上一页/下一页查看。历史按number游标，其他列表仍有深页skip成本；新提交期间不承诺跨请求快照。题库列表只预览最新可见版本，其他版本从历史页查看，导入页仍可选择指定可用版本。

问卷结果权限保持所有者限定，题目共享不开放其他发布者答卷；引用明细也不泄露他人私有问卷。跨卷统计默认逐版本，仅在题型、稳定选项ID/明确映射和单位通过检查后合并；不做匿名跨卷人员去重，也不自动换算单位。

原整卷/单题统计继续保留，原接口文本内容仍整批返回；新增分页针对题库跨问卷内容。没有声称实现跨刷新填写草稿恢复、全新电脑安装、大规模压测、正式业务恢复或缓存。代码和配置在01，技术文档只在本目录4份，完整测试和证据在03，报告/AI日志/基线在04。
