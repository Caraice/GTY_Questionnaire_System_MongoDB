# 关键逻辑说明

本文依据0.11.0版本，保留第一阶段逻辑并补充第二阶段实现，说明身份、稳定ID、版本锁、跳转、校验、保存、匿名和聚合统计的处理流程与设计取舍。测试证据单独放在03_测试用例。

## 已实现的身份与所有权

注册时用户名转小写，密码随机加盐哈希；唯一索引处理并发重名。登录生成随机 token，MongoDB 保存摘要和过期时间；每次请求检查 expires_at，而不等待 TTL 删除。退出删除当前 token 对应会话。所有者来自当前登录用户，不接受请求体指定 owner_id；问卷详情查询同时包含 `_id` 和 `owner_id`，越权统一返回 404。

## 题目编辑与保存 已实现

四种题型可编辑题干、必答和各自校验配置；选择题可增删、排序选项，题目可增删和排序。新增才生成 UUID ID，改写和排序不再生成；后端按输入保留 ID。切换题型保留题目 ID，单选与多选之间保留选项；本次编辑切换为填空再切回也缓存原选项，但改成填空并保存后原选项不再属于该题。切换题型重置校验配置，界面有提示。

Pydantic 拒绝空白题干、空白选项、重复题号/选项 ID 和矛盾配置；保存时去除题干、选项首尾空白。问卷服务校验所有权及草稿状态，并保护既有跳转引用。数据库通过 expected_version 原子更新与加一实现乐观锁。冲突不改变服务器内容；页面保留用户输入并要求明确重新加载，离开或重新加载有未保存提示。

## 逐题答案校验引擎 已实现

配置合法性和答案合法性分开处理。`app/domain/validation.py` 的 `validate_answer(question, value)` 是不访问 HTTP、MongoDB 的纯函数，接收已验证的题目定义，返回合法的规范化答案或抛出 ValueError。0.6.0 的 validate_path 已按服务端真实路径调用，提交服务保存规范化答案。

Submission.answers 使用 `dict[str, JsonValue]`，保留 JSON 布尔、整数、浮点、字符串、数组、对象和 null 的原始类型，不再由联合类型把 true/false 变成 1/0。`allow_inf_nan=False` 拒绝任何嵌套位置的非有限数字，包括溢出指数。字符串 "NaN" 保留为字符串，再由题型校验判断；它作为普通文本可以合法，不能作为数字。

| 题型 | 严格类型与约束 | 返回行为 |
| --- | --- | --- |
| 单选 | 必须为字符串且精确匹配选项 ID，不能用数字或数组，不能靠裁剪空格匹配 ID | 原字符串 ID |
| 多选 | 必须为字符串列表，禁止重复和未知 ID；检查最少、最多及恰好数量 | 新列表，保留原顺序，不静默去重 |
| 文本 | 必须为字符串；裁剪首尾空白后按 Unicode 字符数检查长度 | 裁剪后的字符串 |
| 数字 | 只接受原始 int/float，明确排除 bool 和数字字符串，必须有限；闭区间检查上下限 | 原数字和原数字类型 |

整数限制按数学上的整数判断：1、1.0、0 和 -0.0 可通过，1.5 不通过；不将整数型浮点强制转 int。整数不用 float 转换检查，避免大整数精度损失或溢出；提交服务以 BSON 预编码检查有符号 int64 范围，超出返回 422。浏览器受 JavaScript 精度限制，对整数题另拒绝不安全整数；API 可精确接收 BSON int64 范围内整数。

缺省答案键由调用方传 None。所有题型的 None、单选/文本的空白字符串、多选的空列表视为未填写；必答时拒绝，可选时返回 None。错误类型即使在可选题也拒绝，例如数字空字符串、多选空字符串、文本空数组和 bool。配置 min_choices 或 min_length 不自动把题变成必答。不能用 `if not value` 判断缺失：数字 0 是有效答案，若范围允许就通过。

未知题型直接拒绝，包括空答案。校验不修改原题目或答案。服务端只验证真实路径中的题目，跳过题不执行必答检查；夹带路径外键即使为 null 也拒绝。整数手机号可能丢失前导零，需要保留格式时应选文本题。

请求校验异常的 HTTP 422 只返回 type、loc、msg，不回显 input/ctx，避免 NaN/Infinity 在错误响应中再次触发 JSON 序列化失败。

## 规则定义与跳转执行已实现

规则 PUT 接口保存到 MongoDB，复用草稿状态与 expected_version 乐观锁。validate_rules 检查来源/目标存在、题型与操作符适配、选项引用、有限数字及 between 顺序；禁止自跳、回跳和 END 题号。发布与提交时再次校验存储规则，next_question 和 validate_path 已实现。

按当前题目寻找 rules 中对应规则并依次匹配，首条成功确定目标；无匹配继续下一题；目标 END 或最后一题后结束。发布前校验题号存在、目标向后、运算符与题型及 value 一致。禁止回跳是第一阶段项目选择，不是原文硬要求。

单选eq；多选contains_any/contains_all；数字eq/gt/gte/lt/lte/between，between为闭区间；文本eq/contains，裁剪条件与答案两端空白后区分大小写比较。可选空答案不触发任何规则，数字 0 正常参与比较。validate_path 返回 `(path, normalized_answers)`，遗漏不写答案对象，访问过的可选题仍在 path。错误带 question_id 供前端定位，不信任客户端路径。

提交时从第一题开始，服务端只根据保存的规则与答案计算真实路径。仅校验路径内题目，拒绝未知题号和路径外答案。不能信任客户端给出的“已跳过”或“已完成”。用户返回修改前面答案时，清除不再位于路径上的旧答案。

## 发布期限与真实答卷保存已实现

状态只能 draft → published → closed。发布要求非空且可作答的合法题目、合法规则和未来期限；同一条件更新检查 version 与 status，写入 published 和冻结内容版本 published_version。题目、选项、题序及规则在 published/closed 都禁止修改。期限、关闭等管理操作递增 version，不改变 published_version；旧发布文档缺该字段时兼容读取，并在首次管理写入补齐原 version。

所有者可更新草稿/已发布的截止时间，必须为未来时区时间或显式 null；已截止的 published 可延长或取消期限，手动 closed 不可恢复。availability 不落库，而是按 status 和 deadline 推导，截止判断使用 <=。

GET 与新 POST 复用 require_available，每次先读 MongoDB，再取当前 UTC 时间，草稿 409、关闭/截止 410、不存在 404。GET 只返回公开定义；POST 比较冻结版本、检查匿名、路径与答案，BSON 预编码保证可存储，再执行最终准入写入并插入完整答卷，成功才返回 201。

禁止重复时 attempt_key 固定 once；允许重复时取本次 submission_key，唯一索引处理并发。原始请求以排序后的 JSON 做 SHA256 指纹，不转换答案类型；同账号同问卷同键同内容返回原 id/时间/路径，200 且 replayed=true。同键不同内容返回 409。已保存原请求在截止/关闭后仍可重放回执，不重新准入或新增答卷。数据库故障返回 503，回执不明仍用原键重试，测试包括插入后模拟确认丢失。

最终准入对 surveys 单文档原子匹配 published、冻结版本、应用时间与数据库 $$NOW 的期限条件，并递增 submission_sequence；不改变管理 version，统计也不使用该序号。关闭/期限变更先完成，则后续准入拒绝；准入先完成的请求可在关闭后结束插入。这里明确采用准入的先后，不宣称两个集合事务。准入后宕机可能留下序号空洞、没有答卷；重试按真实 responses 判断。该语义覆盖了关闭前/后准入以及保存确认丢失测试，未声称完成高负载压力测试。

匿名响应的 respondent_id 为 null，问卷内 respondent_key 使用 app_settings 中原子生成且持久保存的 HMAC 密钥计算 survey_id 与登录用户 ID。匿名开关不改变该标识，所以不能绕过禁止重复。API 不返回内部标识/密钥；这是面向创建者匿名，数据库管理员仍可关联，不宣称绝对匿名。密钥需随数据库备份，不随意轮换。

## MongoDB 聚合统计 已实现 API

查询前用 SurveyRepository 验证所有者，再确认可选 question_id 存在。StatisticsService 只组织结果，StatisticsRepository 对 responses 发出一次聚合：先按 survey_id 与 published_version 匹配，再按 submitted_at、_id 排序，使用 `$facet` 同时计算总提交数与每题指标。管理 version 因期限或关闭变化时，统计仍使用冻结的 published_version；草稿及旧发布文档回退 version。

每题分支用 path 判断实际访问，并用 `$getField` 按稳定题号取答案。单选以选项 ID 分组计数；多选先检查非空、集合包含关系、不重复及选择数量，然后 unwind/group 计算次数；answered_count 在 unwind 前统计。文本检查原始类型、trim 与字符长度，再 push 内容。数字只接受 BSON int/long/double，排除 bool、字符串、非有限数与约束外值，整数限制用 mod 检查；push 原数值并用 `$avg` 计算均值。操作符通过 `$cond` 保证类型安全，不能假定相邻 match 或 and 短路。

数字 0 不用真值判断，缺失、null、跳题不补 0。总提交数单独 count，每题有效回答数独立；异常历史答案仅排除该题指标。无答卷时计数 0、内容 []、平均 null。MongoDB 普通 double avg 可能在极大有限数字上溢出，因此先用 toString/toDecimal 保留可往返的数值表示并以 Decimal128 累加，最后将有限平均值转为 double；不直接 toDecimal(double)，避免其 15 位精度舍入使最大有限浮点溢出。平均值仍受浮点精度限制，不宣称任意精度。

服务层按题目/选项定义顺序关联聚合计数，补齐无人选择的选项并隐藏内部身份字段。不持久化统计缓存；每次请求重新聚合。当前一次返回全部文本和数字内容，受 MongoDB facet 100MB 中间结果及 BSON 16MiB 最终文档上限约束，适用于课程样本规模；扩大数据量应将内容列表分页，聚合计数与均值单独保留。

## 第二阶段身份 版本与共享

## 三种 ID 分清楚

| 标识 | 表示什么 | 变化规则 |
| --- | --- | --- |
| template_id | 同一道独立题目 | 保存新版本、恢复时不变；另存为新题时新建 |
| template_version_id | 一次固定内容快照 | 每次版本保存和恢复都新建，原记录不覆盖 |
| question.id / instance_id | 题目在某份问卷中的一次出现 | 每次导入新建，排序及主动升级时保持 |

选择题选项 ID 在版本内容中保留，答案与跳转先按实例 ID 定位，再解释该实例的选项 ID。因此两道重复导入题即使有同名、同 ID 的选项，也不会把回答或规则合并。统计页的标题与筛选补上问卷内题号，方便区分相同题干。

## 并发、中断和冻结

问卷编辑、导入、主动更新都要求严格整数 expected_version，最终写入同时检查问卷所有者、草稿状态和版本。失败返回 409，不覆盖其他窗口的修改。导入成功后需使用响应中的新 version 继续操作；相同旧版本请求重试不会再追加第二道题。希望重复添加时，使用新 version 再发起一次导入。

题目版本保存也检查 expected_version，对应模板的 edit_version。服务先在模板文档内 CAS 预留完整 pending_version，再只插入版本记录，最后推进头版本并清除预留。并发只有一个预留成功。连接中断后，重新加载会按原预留 ID 补齐并完成同一个版本，不重建另一份版本。版本列表只展示已提交头版本及之前的版本。此方案是可恢复的多步写入，不宣称跨集合事务；新建独立题目也不宣称跨集合原子提交。

共享预览不能代替最终使用权限检查。真正导入、另存或更新前，对 active 共享记录做一次条件准入写入；撤销与准入以这次原子写入的先后为准。先撤销则拒绝；已经准入的请求可以在撤销后完成。准入次数不是成功导入数，引用明细必须从问卷实例查出。

发布仍按原逻辑检查题目和规则并冻结嵌入定义。题库产生新版本、恢复或撤销权限，都不会改已发布问卷的题目、published_version 或历史答案。手工在草稿副本中改字也不写回题库，页面会标记“已在本问卷修改”。

## 两个窗口保存同一题

`question_versions.number` 表示内容历史编号，`question_templates.edit_version` 是管理写入的并发令牌。客户端提交 `expected_version` 对比后者，不能拿v2的2替代它。新增确定性用例将管理令牌置为8：带1保存返回409，带8保存成功，内容编号变为2、管理令牌变为9。

每次追加先在题目身份文档做CAS，条件包括所有者、expected_version相等、没有pending_version。胜者把完整不可变版本写进pending_version，版本号按当前内容头加一；失败者409，不能自动刷新令牌重试覆盖。`(template_id, number)` 唯一索引再阻止编号冲突。题目编辑器遇到409保留本地内容并要求重新加载。

单机MongoDB不使用跨集合事务。写入依次为：

1. 原子预留完整pending_version；此时旧当前版本仍可用。
2. 按预留ID以setOnInsert写入版本集合，已有同ID必须逐字段完全一致，不能覆盖。
3. 以pending_version的ID为条件更新latest_version_id、递增edit_version并移除pending。完成后返回本次提交对应的令牌，不能把稍后写入者的新令牌与本次旧内容拼在一个响应里。

预留成功但回执丢失、内容插入前失败、内容已插入而当前指针写入失败，都可以由重新加载自动补齐同一预留；不会重新生成ID或再追加一个编号。指针已经更新但回执丢失时，重新加载读到已提交版本，旧expected_version重试得到409。恢复没有清除超时锁或猜测失败回滚，原始预留保留到可验证地完成。若预留ID/编号对应不同内容，停止恢复并返回409，需备份后检查数据；数据库连接错误返回503，不宣称失败一定未写入。

除已有双窗口竞争和两个中断点测试外，本轮补测预留回执丢失、指针写前/写后丢回执、内容碰撞409、令牌与内容编号分离，以及较晚管理写入不会向旧内容借出新令牌。页面没有自动代用户选择冲突合并。

## 权限和来源为什么这样处理

目前项目的问卷结果查看权限仍是问卷所有者。题目所有者能查看自己的题目定义，但不因此获得其他发布者的答卷；共享接收者也只能统计自己有权查看结果的问卷。两个方向都不开放对方的结果。Repository聚合开头再次带 `owner_id`，不是先查全库再由页面隐藏。

统计从 `surveys.question_sources` 读取在线引用，兼容 `question_usages` 中的旧迁移引用；实际答案键仍是问卷内实例ID。同题多次导入不会混掉题号。来源指纹、不可变版本原始指纹、问卷内归一化内容都要一致，不能只相信 `modified=false`。本地改写后的回答不冒充原版本，问卷本身的统计仍照常保留。

撤销共享后不能新导入，但已经导入自己问卷的内容和结果仍可统计。此时仅开放本人问卷实际引用的版本，来源历史入口按当前源题权限隐藏。版本定义损坏时显示原因，不伪装成正常的零回答统计。

## 合并的判定

- 题型必须相同，单选和多选不能互相合并。
- 选项必须具有相同稳定ID集合，或有显式完整一一映射。相同ID但标签修改时允许合并并提示标签变化，结果显示基准标签及ID。题意是否仍适合合并，需要用户结合版本内容判断，程序不会推断文字语义。
- 数字单位必须明确且一致；缺失单位需要本次确认，已有单位不能被覆盖。不同单位版本列出排除原因。
- 文本、数字范围及多选数量限制允许不同，但有效性始终依照各自版本校验。选项映射发生在原答案验证之后。
- 配置只用于本次查询；不修改来源、版本、问卷、选项ID、答案或权限。请求中最多选择32个版本，且只能属于当前题目和当前可统计范围。

## 代码、数据库和兼容

路由在 `app/api/library.py`，范围与兼容规划在 `app/services/library_statistics.py`，合并判定在 `app/domain/statistics_merge.py`，聚合在 `app/repositories/library_statistics.py`，页面为 `web/library-statistics.*`。原问卷统计复用同一套 MongoDB 答案验证表达式，防止两种入口的0、空白、类型规则不一致。

MongoDB从有权查看的问卷出发，按 `published_version`（旧数据缺省用 `version`）关联 `responses`。`$lookup` 后分别计算答卷数和实例回答；`$getField` 读取稳定实例ID的答案，结合 `path`、类型和原版本限制筛选，`$group` 计算次数，数字经字符串转Decimal128做中间平均后返回double，避免大double累加溢出。各指标由一个顶层 `$facet` 组织，没有嵌套facet。Python只处理版本、范围和映射元数据，不读取答卷后自己求和。

跨卷统计复用问卷所有者/来源索引与答卷 `versioned_statistics` 复合索引（问卷、冻结版本、提交时间、ID）。`NumberQuestion.unit` 是可选内容字段；归一化去掉缺省的 `unit=null`，保留旧内容指纹含义，不更新旧版本BSON。旧问卷和答卷不要求重写；尚未建立来源的旧题按原迁移流程显式演练、迁移，不按标题猜来源。
