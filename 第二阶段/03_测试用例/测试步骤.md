# 测试步骤

## 准备

保持四个文件夹同级；先按 ../01_可运行代码/配置说明.md 创建 .venv、安装 requirements-lock.txt 并启动MongoDB。自动化测试还需Node.js，本项目本机实际使用的版本会写入测试结果。自动化直接创建应用，不要求API服务器已启动；浏览器手工测试需Start.cmd启动API。

测试连接默认 mongodb://127.0.0.1:27019；自定义连接需在同一PowerShell窗口设置MONGODB_URI。测试账号与业务数据在随机UUID隔离库中创建，库名前缀为survey_test_等，不清空原业务库。测试库保留可供查询，需要具备创建库/集合/索引的权限。不要用会被他人并发修改的演示库做手工结果对照。

## 自动执行全部测试

在“03_测试用例”打开PowerShell：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\运行全部测试.ps1
```

脚本强制开启RUN_MONGO_TESTS=1，先跑18个Python文件，再跑7个Node文件。输出写入测试输出/提交副本本轮/Python测试.log、Python测试.xml、Node测试.log。缺MongoDB、Python、Node或依赖均不应视为通过。默认解释器是同级01_可运行代码/.venv/Scripts/python.exe；也支持明确复用本机已有环境：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\运行全部测试.ps1 -PythonExe '你的现有虚拟环境\Scripts\python.exe' -NodeExe '你的node.exe路径'
```

也可分别运行：

```powershell
$env:RUN_MONGO_TESTS = '1'
$env:PYTHONDONTWRITEBYTECODE = '1'
..\01_可运行代码\.venv\Scripts\python.exe -B -X utf8 -m pytest -q -s -p no:cacheprovider --junitxml=测试输出/手动重跑/Python测试.xml
node --test 自动化测试/test_editor_state.mjs 自动化测试/test_survey_state.mjs 自动化测试/test_fill_state.mjs 自动化测试/test_view_state.mjs 自动化测试/test_rules_state.mjs 自动化测试/test_library_state.mjs 自动化测试/test_library_statistics_state.mjs
```

当前版本预期Python409项通过、失败/错误/跳过均为0，Node25项通过、0失败。不要把未开启集成测试时的“部分通过、其余跳过”当成完整验收。实际结果见测试结果.md；每项详细输入与断言见自动化测试代码，重点用例的步骤/输入/输出/结果整理在测试用例.md。


## 本人页面验收顺序

1. 在01启动API，确认health为0.11.0。先按02/系统说明走一遍原创建、加题、跳转、校验、发布、填写、回看与统计；不要因新功能而省略第一阶段检查。
2. 注册A和B，A新建题库并保存四种题型；在版本历史共享v1给B。B从“共享给我的题目”导入，发布并保存答案；数字填写0，文本写“旧回答”。
3. A编辑v1保存v2，B旧问卷与原统计应不变。B草稿导入v1；未获v2共享前不得升级；A共享v2后B主动升级，实例ID和排序不变。
4. 已发布卷升级应409。A恢复v1生成新的v3，v1/v2仍存在；撤销v1/v2后B不得新导入，原问卷和结果继续保留。自动化贯穿对四种题型均执行。
5. 在两个窗口加载同题同管理令牌，分别修改保存，应只有一个成功，另一方409并保留本地内容；重新加载核对版本历史。不要手工改库模拟宕机，故障恢复由自动化注入验证。
6. 题库/题目超过20、历史超过10版、引用超过20实例、跨卷文本超过100条时点下一页；计数与均值应不随内容页改变。
7. 题目卡片进入跨卷统计，按版本核对问卷/答卷/回答三项数；数字0计入，跳题排除。ID不同的选择题要明确映射，单位不一致排除，私有问卷不出现在别人结果中。

## 可选迁移与固定数据测量

在01按配置说明准备副本数据库，先预检002再显式apply，重复执行不得新增重复记录或改变原题号。正式库不应直接作为试验目标。

固定数据测量在01运行 `python -m scripts.benchmark_library_queries`，需要显式设置MONGODB_URI；每次生成独立合成库并保留，包含3000题/5000版/2000问卷/10000答卷。现成explain在测试输出的历史开发验证中；这些耗时不是当前电脑重新跑出的结果，也不等于压力测试。

真实结果见测试结果.md。未设置RUN_MONGO_TESTS导致跳过、数据库连接错误、只跑部分用例，都不能称为完整通过。测试输出保留独立开发历史与提交副本本轮两组证据，不累加两组测试数量。
