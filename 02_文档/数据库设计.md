# 数据库设计

版本0.8.0，MongoDB原生驱动PyMongo；所有账号、会话、问卷、答卷与内部持久配置均保存在MongoDB。

## 集合划分

| 集合 | 文档粒度 | 关键字段 | 嵌入或引用的理由 |
| --- | --- | --- | --- |
| users | 一个账号 | _id、username、password_hash、created_at、schema_version | 用户独立生命周期，不把账户信息复制到问卷 |
| sessions | 一次登录 | user_id、token_hash、created_at、expires_at | 可注销、过期；引用用户 ID；TTL 回收 |
| app_settings | 一项内部配置 | _id、schema_version、secret | 保存 HMAC 持久密钥，与业务答卷分离，跨重启稳定且不由 API 暴露 |
| surveys | 一份问卷定义 | owner_id、share_id、title、description、status、deadline、allow_anonymous、allow_multiple、questions、rules、version、published_version、schema_version | 题目和规则随问卷读取，嵌入便于原子更新；当前最多 200 题为实现边界，非教师要求 |
| responses | 一次有效提交 | survey_id、survey_version、respondent_key、respondent_id、anonymous、answers、path、attempt_key、submission_key、request_hash、submitted_at | 答卷持续增长，独立集合支持并发插入；原始请求指纹用于幂等核对 |

不把所有数据装进一个集合，也不按“每种题型一张表”机械复制关系数据库设计。不同题型在问卷内有不同的嵌套 validation，适合文档建模。用户和答卷使用引用是控制冗余的取舍，不表示 MongoDB 禁止引用或关系数据库无法实现问卷。使用 MongoDB 首先是课程硬要求，其次是该模型与可变题型结构相适应。

## 问卷定义示意

```json
{
  "_id": "survey-uuid", "schema_version": 1, "version": 1,
  "owner_id": "user-uuid", "share_id": "random-share-id",
  "title": "校园调查", "description": "示例",
  "status": "draft", "deadline": null,
  "allow_anonymous": true, "allow_multiple": false,
  "questions": [
    {"id":"q1","type":"single","title":"是否在校","required":true,
     "options":[{"id":"yes","label":"是"},{"id":"no","label":"否"}],"validation":{}},
    {"id":"q2","type":"number","title":"年龄","required":true,
     "validation":{"minimum":0,"maximum":120,"integer_only":true}}
  ],
  "rules": [{"source_question_id":"q1","operator":"eq","value":"no","target_question_id":"END"}]
}
```

示意省略创建、更新时间；实际 MongoDB 保存 BSON Date，统一 UTC，API 返回带时区 ISO 时间，页面转换显示。题目 ID 和选项 ID 稳定，不能用数组下标作为持久 ID。题目顺序由 questions 数组决定。跳转目标和答案使用这些稳定 ID。

## 索引与一致性

| 集合 | 索引 | 作用 |
| --- | --- | --- |
| users | username 唯一 | 小写标准化后避免重名，依靠唯一索引防并发注册冲突 |
| sessions | token_hash 唯一；expires_at TTL | 会话查询和回收；API 另检查过期时间，不能依赖 TTL 及时删除 |
| surveys | share_id 唯一；owner_id + created_at | 分享链接定位；按所有者列出问卷 |
| responses | survey_id + submitted_at | 整卷统计与时间检索 |
| responses | survey_id + survey_version + submitted_at + _id | 同冻结内容版本统计和内容列表稳定排序 |
| responses | survey_id + respondent_key + attempt_key 唯一 | 不允许重复时 attempt_key=once，原子防止并发重复；允许时取本次提交键 |
| responses | survey_id + respondent_key + submission_key 唯一 | 请求重试幂等，避免同一次提交重复记数 |

当前 schema.py 建立这些索引，0.6.0 已接入实际写入策略并完成真实并发与重试测试。准入写入会串行修改问卷的一项内部序号，不把该序号当提交总数，也未声称无写热点或已完成压力测试。

数据库 validator 检查基础字段、类型与状态；Pydantic 检查接口结构、配置边界和唯一题号。JumpRule 的题型适配、引用和前向顺序由已实现的规则定义校验检查；domain/routing已负责执行和路径重建。答案合法性需要服务端业务校验，不能只靠 schema。

## 答卷和匿名策略

非匿名保存 respondent_id；匿名置空，创建者统计不返回身份。使用 app_settings.response_hmac 的持久密钥按带分隔的 survey_id 与 user_id 计算 HMAC respondent_key，匿名切换保持同一问卷内标识，防止绕过重复限制。密钥原子 setOnInsert、跨重启保持，应随数据库备份且不随意轮换；不由 API 返回。此方案面向创建者匿名，数据库管理员仍可能关联，不宣称绝对匿名。

答案以题号到值的对象保存；单选存选项 ID，多选存校验无重复的选项 ID 数组（不静默去重），文本裁剪首尾空白，数字保留原始有效数值。path 来自服务端重建，禁止客户端指定；未知或路径外答案拒绝。遗漏不写答案对象，路径仍包含访问过的可选题。统计只使用同问卷同冻结版本的已保存答卷，跳过/空值不进入单题分母，0计入。独立聚合测试仍预置样本，另有真实 POST 到保存再聚合的端到端测试。

## 状态和内容版本

已实现状态：draft → published → closed。发布前重新验证所有题目、规则及期限，published/closed 的题目与规则冻结。超过 deadline 后状态仍可为 published，但派生 availability 为 expired；填写和提交每次重新读库并检查当前 UTC 时间，deadline <= now 时拒绝。过期 published 可通过未来期限或取消期限恢复访问；手动 closed 不可重新开放。

题目、规则、发布、关闭和期限更新都使用 `expected_version` 乐观锁：按 `_id + owner_id + status + version` 原子更新对应字段、updated_at 并递增 version。预检查用于友好报错，条件写入才是并发保证；发布与修改题目、关闭与改期限的竞争均有真实 MongoDB 测试。规则保存、执行与路径重建均已实现；准入内部序号不递增管理版本。

version 现为管理修订号。新增可选 published_version 在发布时等于发布后的 version，表示冻结的内容版本；后续期限/关闭只递增管理版本，published_version 不变。旧已发布文档若没有该字段，读取回退到现有 version，首次管理写入补写该基线；不清空旧集合，不替换 validator，不需破坏性迁移。schema_version 仍表示文档结构代际。

0.6.0 提交保存已实现。最终准入点为 surveys 上条件原子写入 submission_sequence，匹配 published、冻结版本及应用/数据库时钟下未到期；不改管理 version。先准入的请求可在关闭后完成 responses 插入；关闭/期限变更先发生则拒绝。两集合不是事务，准入序号可能有空洞；统计只聚合真实答卷。插入或确认失败返回503，原键重试恢复；同请求已保存的回执可在关闭/到期后重放，不新增。


## Schema文件与后续兼容

可执行定义位于 ../01_可运行代码/database/schema.py；schema.json 为全部5个集合 validator 的直接导出，indexes.json 为 initialize 实际索引调用的导出。嵌套题目/规则的约束由 app/models.py 和 app/domain 补充，不声称当前数据库 validator 能独立拒绝所有业务错误。每个集合还有MongoDB默认的_id唯一索引。

初始化命令及连接配置见 ../01_可运行代码/配置说明.md。已有集合不会被启动程序删掉或静默替换validator；schema_version保留为1，后续在database/migrations内增量迁移。0.7/0.8视图与文本规则扩展没有要求重建业务库。历史记录按持久HMAC查询，匿名记录不增加明文用户字段；历史列表分页，构造查询随问卷数增长，目前未验证大规模性能。
