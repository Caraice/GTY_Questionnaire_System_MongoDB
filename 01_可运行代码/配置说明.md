# 配置说明

## 环境和解释器

本次实际验证环境为 Windows、Python 3.14.6、MongoDB 8.0.17。项目按 Python 3.11+ 编写，但未逐一验证所有 Python/MongoDB 版本。Node.js 只用于前端状态测试，运行网页不需要 Node 或 npm 构建。新电脑需自行安装 Python 和 MongoDB；提交包不携带虚拟环境、数据库程序或业务库。

在“01_可运行代码”打开 PowerShell，执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
```

requirements-lock.txt 是实际验证环境的完整依赖锁定；requirements.txt、requirements-dev.txt 保留兼容范围。安装失败应处理报错，不要跳过依赖安装。本次整理后的测试复用原电脑依赖，不等于在新电脑完成了安装验证。

首次解压后，必须先完成以上安装再双击Start.cmd；提交包不含.venv，因此直接双击可能提示解释器不存在。原开发目录已有.venv，不代表本提交目录也已有。每个副本都应有自己的虚拟环境。

若Anaconda在创建虚拟环境的ensurepip阶段失败，但当前Python已有pip，可改用：

```powershell
python -m venv --without-pip .venv
python -m pip --python .\.venv\Scripts\python.exe install pip
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
```

## 方式一 由脚本启动本机 MongoDB

将下面的程序路径换成自己安装的 mongod.exe，不能直接照抄占位路径。在同一个 PowerShell 窗口执行：

```powershell
$env:MONGOD_EXE = 'C:\MongoDB\bin\mongod.exe'
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start.ps1
```

脚本先检查默认连接 mongodb://127.0.0.1:27019，连不上时才启动 MongoDB，数据目录为本目录下 .runtime/mongo-data，日志为 .runtime/mongod.log。默认业务库 survey_stage1，API 监听 127.0.0.1:8000。MongoDB 与 API 分开运行，关闭 API 窗口不会停止 MongoDB。MongoDB 程序路径可在启动窗口中设置后执行 Start.cmd。原开发机有课程 lab2 程序的后备路径；提交到别处请显式设置 MONGOD_EXE，不依赖课程目录。

## 方式二 使用已经运行的 MongoDB

```powershell
$env:MONGODB_URI = 'mongodb://127.0.0.1:27017'
$env:MONGODB_DB = 'survey_stage1'
$env:HOST = '127.0.0.1'
$env:PORT = '8000'
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start.ps1
```

自定义 URI 的数据库必须已启动且允许当前连接；脚本只会自动启动默认本地 27019 实例。URI 如含凭证，不应写入提交材料或测试截图。

## 配置项

| 配置项 | 默认值 | 含义与读取位置 |
| --- | --- | --- |
| MONGODB_URI | mongodb://127.0.0.1:27019 | 连接地址，app/config.py 和连接检查读取 |
| MONGODB_DB | survey_stage1 | 业务库名，app/config.py 读取 |
| MONGOD_EXE | 无通用默认值 | scripts/start.ps1 启动本机数据库时使用的程序路径 |
| HOST | 127.0.0.1 | scripts/start.ps1 传给 uvicorn |
| PORT | 8000 | scripts/start.ps1 传给 uvicorn |
| RUN_MONGO_TESTS | 不启用 | 测试脚本设为1，启用真实MongoDB集成测试 |

**.env.example 仅供参考，不会自动加载；仅复制为 .env 不会生效。** PowerShell 的 `$env:...` 对当前窗口及其子进程生效，换窗口需重新设置。启动脚本固定使用本目录 .venv/Scripts/python.exe，不读取 PYTHON_EXE。会话默认24小时由 Settings 默认值决定，不存在 SESSION_HOURS 环境变量开关。

## 初始化与启动确认

```powershell
# 仅连接并初始化集合和索引，不启动API
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start.ps1 -CheckOnly
# 已连接数据库时，也可直接初始化
.\.venv\Scripts\python.exe -m scripts.init_db
Invoke-RestMethod http://127.0.0.1:8000/health
```

健康检查应返回 status=ok、database 为配置库名、version=0.8.0。初始化执行 database/schema.py 的 initialize，创建缺少的5个集合及索引，不清空旧数据，不静默覆盖已有 validator。schema.json 与 indexes.json 是可读导出，实际初始化入口仍是 schema.py。完整嵌套规则与答案检查还由 app/models.py 和 app/domain 执行，不能把基础 BSON validator 当作全部业务校验。

打开 http://127.0.0.1:8000 为网页，/docs 为开发者交互式 API 参考，/openapi.json 为机器可读接口定义。日常规则配置和查看统计使用网页按钮。无需预置演示账号，先自行注册。

## 常见问题和数据保留

- 提示解释器不存在：回到本目录创建 .venv；不能用旧电脑的虚拟环境代替安装。
- MongoDB连接失败：确认 URI、端口和 mongod.exe 路径；检查 .runtime/mongod.log。
- 8000被占用或看到旧界面：核对 /health 版本；停止自己之前启动的旧API后重启，或设置其他PORT。不应结束无关程序。启动脚本可能复用同库旧服务，所以不能只凭“已运行”判断版本。
- 页面401：重新登录；凭证保存在浏览器当前页签的 sessionStorage，同一页签登录后打开分享链接最直接。
- 页面409：先保留本地修改，再重新加载最新版本；不要盲目重试覆盖。
- 页面410：问卷已截止或关闭；发布者可对尚未手动关闭的问卷修改期限。
- 重复初始化不能当作结构迁移；后续修改 validator 需要明确迁移。备份业务库应包含 app_settings 内的持久HMAC密钥，否则旧匿名历史识别会受影响。源码ZIP不含业务库，不能替代数据库备份。

完整测试入口在 ../03_测试用例/测试步骤.md，测试使用隔离库，不清空已有业务库。全套运行后会保留测试库，便于复核；并发用例不等于大规模负载测试。
